An Entire plugin is a separate program named `entire-NAME`. The CLI runs it when you type `entire NAME …`. Two commands let you do that from the editor:

- **Entirely: Run Plugin Command** (`entirely.runPluginCommand`) picks a plugin, reads what it accepts from its own help, confirms, runs it, and shows the output.
- **Entirely: Install Plugin** (`entirely.installPlugin`) installs a plugin from the plugin index by its bare name.

Entirely has no plugin list of its own beyond the names in `entirely.suggestedPlugins`. What a plugin accepts is read from the plugin at run time.

<Aside type="caution" title="Install is not verified against a live index">
Plugin install runs `entire plugin install` with the flag that skips the CLI's prompt. That flag is read from `entire agent-help plugin install`. The install flow is tested against a fake CLI. It has not been exercised against the real plugin index.
</Aside>

## Run a plugin command

<Steps>

1. Run **Entirely: Run Plugin Command**.

   The picker lists the plugins `entire plugin list` holds, plus every name in `entirely.suggestedPlugins` that is not installed (marked "not installed"). You can type a name that is not listed.

2. Pick a subcommand, if the plugin has any.

   Entirely reads `entire agent-help NAME`, and falls back to `entire NAME --help`. Subcommands from either layout are offered as a list.

3. Type the arguments.

   The plugin's own flags are shown as you type. Quoted phrases stay together. At most 64 arguments are accepted, and control characters are refused.

4. Read the confirmation and agree.

   The dialog shows the exact command line and says the plugin runs as a named login. For example: "It runs as github:alice (login alice@us.auth.entire.io). A plugin is a separate program, and what it does is up to the plugin." If no login can be worked out, nothing runs and you are asked to sign in.

5. Read the output.

   While it runs, a progress notification offers cancel. The output opens in a read-only document. If the plugin prints nothing, you get a message saying it finished and printed nothing.

</Steps>

### Who the plugin runs as

The CLI's `--context` flag does not reach plugin processes. The login reaches a plugin only through the `ENTIRE_CONTEXT` environment variable, which Entirely sets for the command from the login named in the confirmation. The confirmed login and the login used are the same value. See [Accounts and contexts](/entirely/concepts/accounts-and-contexts/).

### What reaches the log

Everything after the plugin name is what you typed: a prompt, a query. In the `Entire` output channel the command line shows the plugin name and the words as `<redacted>`. The plugin's output is not written to the channel either. It goes to the document you see. See [Privacy and redaction](/entirely/concepts/privacy-and-redaction/).

### The plugin is not installed

When the CLI says the plugin is missing, Entirely names it and offers to install it instead of showing a command failure. The real CLI's message for a plugin it knows of, such as `graph`, `investigate` or `brain`, is:

```text
the entire-NAME plugin is not installed; run 'entire plugin install NAME' and retry
```

For a name the CLI does not know, it says `unknown command "NAME"`. Entirely recognises both. The offer reads: `The "NAME" plugin is not installed. Install it with "entire plugin install NAME", or choose Install Plugin.` Accepting it starts the install flow.

## Install a plugin

<Steps>

1. Run **Entirely: Install Plugin**, or click **Install** on a `not installed` row in the [Integrations view](/entirely/guides/integrations-and-mcp/).

   From the command, a picker lists the suggested names that are not installed. You can type another name.

2. Read the confirmation.

   It shows `entire plugin install NAME` and says Entire downloads the plugin named NAME from its plugin index into your plugin directory, as the named login. The plugin is an executable and runs with your permissions. Dependencies it declares are installed too.

3. Agree and wait.

   Entirely runs `entire plugin install --<skip-prompt flag> -- NAME`. On success it says the plugin is installed and points you to Run Plugin Command.

</Steps>

Only index names are accepted: letters, digits, dashes and underscores, up to 41 characters, starting with a letter or digit. A URL or a path is not a plugin name here. If your CLI has no flag that installs without a prompt, Entirely says "this version of the Entire CLI cannot install a plugin without a prompt; update the CLI" and does nothing.

## Names that are also CLI commands

Entirely refuses to run a plugin whose name is also a command of the CLI itself, for example `session`, `status` or `mcp`. The reason is the confirmation. Running `entire NAME …` for a built-in would run that command without its own confirmation in Entirely, so the plugin flow must not become a way around it. The message reads `"NAME" is a command of the Entire CLI itself, not a plugin`.

Visible commands are read from the CLI's help at the time. Hidden commands such as `mcp` and `completion` are in no listing, but the CLI answers their `--help`. A name the CLI answers that `entire plugin list` does not hold is treated as a built-in.

### PATH-only plugins

`entire plugin list` shows only the managed plugin directory. A plugin that lives only on your `PATH` as `entire-NAME` is not listed. The Integrations view can show it as `available on PATH`. **Run Plugin Command** may still refuse it, because the same check that catches hidden built-ins sees a name the CLI answers and the list does not hold. If that is your plugin, run it in a terminal, or install it through `entire plugin install` so the CLI lists it. This is a known limitation, and no hardcoded list of built-ins is kept to work around it.

## Manage plugins

These commands are on the Integrations view and in the palette. Each one that changes something asks first, in a modal that names the plugin and the login it runs as, runs once, and is never retried. The result is read from a fresh `entire plugin list`, so a change is reported only when the list shows it.

<Aside type="caution" title="Tested against a fake CLI">
The real CLI's output for `plugin search`, `plugin info`, `plugin index update`, `plugin upgrade`, `plugin remove` and a failing `plugin doctor` was never captured, because running them would change the machine. They are tested against a fake CLI with invented output. The listing format and a healthy `plugin doctor` were observed.
</Aside>

| Command | What it does |
|---|---|
| **Entirely: Search Plugin Index** | Asks for a term (it may be empty), runs `entire plugin search`, and lists the results with their descriptions and an `installed` marker. Pick one to see its Info or to Install it. Install runs the same question as **Install Plugin**. A name that is also a CLI command cannot be installed. If the CLI's text has no row Entirely can read, you see the text itself. The term is kept out of the log. |
| **Entirely: Plugin Info** | Shows what the index and the install manifest say about a plugin (`entire plugin info`). Works for a plugin that is not installed. No question. |
| **Entirely: Upgrade Plugin** | On a managed row. The modal names the plugin, its installed version, that the newest release is downloaded and checked against `checksums.txt` when one is published, the managed directory and the login. The CLI has no dry run, so the newest version is not shown. Afterwards: "graph upgraded from v0.4.0 to v0.5.0", or "graph is still at v0.4.0" (pinned and linked plugins are skipped, and a plugin already on its newest tag stays). Exit 0 alone is never taken as a change. |
| **Entirely: Upgrade All Plugins** | One modal lists every installed plugin and version. The all flag is read from `entire agent-help plugin upgrade`. The result lists each plugin as changed or unchanged; more than three lines open in a document. |
| **Entirely: Remove Plugin** | On a managed row. The modal names the plugin, the directory and the file it is deleted from, and the login. Success is declared only when a fresh `plugin list` no longer holds it. If the CLI refuses because other plugins depend on it, its text is shown and a second, separate question offers **Remove Anyway** (a new action using the force flag read from the help, not a retry). If a copy is still on your `PATH`, you are told. |
| **Entirely: Update Plugin Index** | Asks, naming the login and saying no plugin is installed or changed, then runs `entire plugin index update`. A failure shows the CLI's reason and "The index was not refreshed." The CLI says nothing about what changed, so a success says there is nothing to read back. |
| **Entirely: Check Plugins** | Runs `entire plugin doctor`. The exit status is the verdict: 0 shows "Plugins: healthy", anything else shows "Plugin check found problems." with **Open Details** for the CLI's text. The doctor report gets a line with the verdict. |

### Plugins outside the managed directory

A plugin that sits on your `PATH` and not in the managed directory shows **Info** only. The CLI cannot upgrade or remove it, and says so: "delete this binary by hand to remove it." Remove and Upgrade are not offered on it, and asking for them by name runs nothing.

### Older CLIs

Each command checks `entire agent-help plugin <subcommand>` first. A CLI without it gets "this version of the Entire CLI has no "plugin remove"; update the CLI" and nothing runs. No flag is written into the extension: the all and force flags are found in the help text.

### The plugin index

The index URL belongs to the CLI (`ENTIRE_PLUGIN_INDEX_URL` or its built-in default). Entirely passes no `--index` and has no setting for it. `plugin browse` is not offered: it is an interactive picker that needs a terminal, and search plus install replace it.

## Settings

| Setting | Default | Range | What it does |
|---|---|---|---|
| `entirely.pluginTimeout` | `120` | 10 to 1800 | Seconds to wait for a plugin to run, or for a download, search, upgrade, removal or check to finish. A plugin is never started again after a timeout. |
| `entirely.suggestedPlugins` | `["graph", "investigate", "brain"]` | | Names offered in the picker and shown in the Integrations view. |

## Failure messages

| Message | Cause |
|---|---|
| "A plugin command is already running." | One plugin command or install runs at a time. |
| "That is not a plugin name. Use letters, digits, dashes and underscores." | The name does not fit the rule above. |
| "Plugins cannot be listed: …" | `entire plugin list` failed. |
| "The NAME plugin cannot be run: …" | Its help could not be read, or the name is refused. |
| "The index was not refreshed: …" | `entire plugin index update` failed. |
| "NAME was not removed: …" / "NAME was not upgraded: …" | The CLI refused or failed; its reason follows. |
| "The CLI said it removed NAME, but NAME is still listed." | Exit 0 with the plugin still in a fresh list. |
| "The NAME plugin failed: …" | The plugin exited non-zero. A timeout adds a hint to raise `entirely.pluginTimeout`. |
