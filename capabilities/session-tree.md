# Session Explorer

> **Capability**: `session-tree` — behavioural contract the system must satisfy.

## Description

Shows every session Entire tracks for the current repository, live and finished, and opens a session's detail on demand.

## Requirements

- MUST source sessions from `entire session list --json`, which returns worktree paths across the whole repository rather than only the open folder.
- MUST show, per session, the agent, its status, the branch, the turn and checkpoint counts, and the last prompt.
- MUST refresh the tree when a session's status changes, and MUST NOT poll more often than the refresh interval allows.

## Scenarios


### Scenario: list-sessions

- **WHEN** the user opens the Entire view in a tracked repository
- **THEN** the tree lists each tracked session with its agent, status, branch and counts

### Scenario: session-detail

- **WHEN** the user selects a session
- **THEN** the session's details are shown, including its last prompt and its checkpoint count

### Scenario: empty-repository

- **WHEN** the repository has no tracked sessions
- **THEN** the tree shows an empty-state message that explains how sessions get recorded
