# Agent Hook Bridge

> **Capability**: `agent-hooks` — behavioural contract the system must satisfy.

## Description

Reports editor-side agent activity to Entire so the editor's own work is captured in the same session history as the CLI's.

## Requirements

- MUST speak the Copilot CLI hook protocol by invoking `entire hooks copilot-cli <event>` with the event payload as JSON on stdin.
- MUST map editor events onto the nine Copilot CLI hook events: SessionStart, UserPromptSubmitted, PreToolUse, PostToolUse, SubagentStart, SubagentStop, SessionEnd, AgentStop and ErrorOccurred.
- MUST preserve the CLI's own convention that a missing `entire` binary is a silent no-op, and MUST NOT surface hook failures as user-visible errors.
- MUST NOT block the editor on hook delivery; a hook that has not completed MUST never delay a user action.

## Scenarios


### Scenario: session-start

- **WHEN** the extension activates in a tracked workspace
- **THEN** a SessionStart hook is delivered carrying the session identifier and workspace path

### Scenario: tool-use

- **WHEN** the user invokes a file-editing tool through the extension
- **THEN** a PreToolUse and a matching PostToolUse hook are delivered for that invocation

### Scenario: cli-absent

- **WHEN** the `entire` binary cannot be found
- **THEN** hook delivery is a silent no-op and the editor behaves exactly as if the bridge were not present
