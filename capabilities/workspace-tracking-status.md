# Workspace Tracking Status

> **Capability**: `workspace-tracking-status` — behavioural contract the system must satisfy.

## Description

Knows, at all times, whether the current workspace is tracked by Entire, which agents are integrated, and which session is live.

## Requirements

- MUST read tracking state from `entire status --json` and MUST parse it defensively, because the JSON carries nullable fields when the workspace is not a repository.
- MUST surface tracking state in the status bar with a distinct visual treatment for tracked, untracked, and error states.
- MUST refresh when the user switches workspaces, when the Git HEAD changes, and when an agent hook fires.

## Scenarios


### Scenario: tracked-workspace

- **WHEN** the workspace is a Git repository with Entire enabled
- **THEN** the status bar shows the tracked state together with the active session when one exists

### Scenario: untracked-workspace

- **WHEN** the workspace is a Git repository but Entire is not enabled for it
- **THEN** the status bar offers an enable action rather than showing an error

### Scenario: not-a-repository

- **WHEN** the workspace is not a Git repository
- **THEN** the status bar shows an inert state and no enable action is offered
