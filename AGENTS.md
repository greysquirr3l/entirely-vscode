# AGENTS.md

## Project

entirely — Entirely is a Visual Studio Code extension for Entire, a Git forge built for
agent-human collaboration.

Entire's CLI records each coding-agent session, freezes it into a checkpoint,
and publishes the history so a team can see what every agent did and why. The
CLI is a terminal tool; everything it exposes is invisible from the editor.
Entirely surfaces it: a status bar that always knows whether the current
workspace is tracking, a tree of live sessions, checkpoint history that opens
straight into the diff, the ability to start a tracked agent turn from the
editor, and an inline blame-style "why does this line exist" query.

The extension never re-implements Entire. It discovers the installed CLI,
reads its JSON output, and shells out for anything mutating. If the CLI is
missing, the extension degrades to a clear, actionable message rather than
failing obscurely.

## Rules

- TypeScript strict mode is already on. Do not weaken it, and do not add `any` to make a type error go away — model the shape instead.

- Keep `src/lib/` free of any `vscode` import. Everything there is plain TypeScript and must be unit-testable without an extension host.

- The `vscode` module may only be imported from `src/extension.ts`, `src/commands/`, `src/providers/`, and `src/services/`.

- Every command, provider, watcher, and disposable must be pushed onto `context.subscriptions`. A leaked listener is the number-one extension bug.

- The Entire CLI is the source of truth for its own behaviour. Never hardcode a flag list — read `entire agent-help <command>` at runtime instead.

- The CLI may be missing, old, or on a machine where it is not on PATH. Every code path that touches the CLI must handle absence explicitly.

- No `entire` invocation may block the extension host for more than a second without yielding to the event loop.

- Never log a full checkpoint payload or a prompt body to the output channel by default; offer it behind an explicit command instead.

- Follow the extension's own style: no `any`, no non-null assertions on values the CLI could omit, no floating promises.

- Prefer declaring a VS Code setting over hardcoding a value. Anything a user may reasonably want to change needs a setting with a sensible default.

- Never hardcode a model name, model id, provider name or context-window size. The user may be on a BYOK model from any provider, or a local model. Treat every model as an opaque string.

## Claude hooks

A `.claude/settings.json` is generated alongside these files. It registers a
`PreCompact` hook that blocks context compression while any task is in the `[~]`
(in-progress) state, preventing the loss of mid-task context.

- Do **not** delete or edit `.claude/settings.json` manually
- The hook exit-code controls: `0` = safe to compact, `1` = blocked
- If you need to override, close the `[~]` task first (mark it `[!]` or `[x]`)
